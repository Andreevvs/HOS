# Критерий выделения самостоятельного фрейма

## Правило

Различие внешнего действия само по себе не является основанием для создания нового F-кода.

Новый способ исполнения уже существующего механизма считается **реализацией существующего фрейма**, если сохраняется его основная тренируемая операция и механизм воздействия.

Новый F-код создаётся только тогда, когда кандидат содержит **отличающийся механизм / тренируемую операцию**, а не просто иной внешний способ выполнения.

## Требование к карточке конкретного фрейма

Каждая карточка конкретного F должна содержать раздел **«Примеры реализации из материалов HOS»**.

В этот раздел включаются различные конкретные способы исполнения данного фрейма, которые действительно присутствуют в материалах проекта (курс, блог, транскрипты и другие авторские материалы HOS).

Примеры не должны придумывацца для полноты каталога. Если в материалах найден только один пример, фиксируется только он. Дополнительные примеры могут добавляться по мере обнаружения в источниках.

## Следствие для каталога

Несколько конкретных действий могут быть примерами одного фрейма.

Например, в рамках [[07 — Техники/01 — Фреймы/F26 — Позитивный контакт с незнакомцем|F26 «Позитивный контакт с незнакомцем»]] в материалах HOS встречаются такие реализации:

- перемигнуться с незнакомцем;
- приятно поговорить с незнакомым человеком;
- подарить цветок незнакомому человеку.

Во всех этих случаях сохраняется одно ядро: инициировать позитивный контакт с незнакомым человеком и получить позитивный возврат коммуникации. Поэтому отдельные F-коды для каждого внешнего действия не создаются.

## Архитектурное назначение

Правило ограничивает бесконтрольное размножение сущностей в каталоге фреймов и отделяет **фрейм как механизм** от **конкретной реализации фрейма**.

Одновременно требование сохранять реальные примеры из материалов HOS не позволяет формализации потерять практическое содержание исходной методологии.
