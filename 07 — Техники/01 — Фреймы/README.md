# Фреймы

**Класс:** техника HOS

## Определение

Фрейм — локальное воздействие, предназначенное для изменения ситуативного тона (СУТ) в текущем контексте.

## Архитектурное правило кодирования

**Fxx = только конкретный фрейм.** Классы, группы, семейства, механизмы и композиционные конструкции F-код не получают. F-коды — стабильные идентификаторы и не перенумеровываются из-за пропусков.

## Основная классификация

### Проактивные фреймы

Активный = проактивный. Основная классификация — по линии развития / виду интеллекта, способность которого человек реализует и локально тренирует при выполнении фрейма. Общий эффект повышения СУТ сам по себе не означает принадлежности к эмоциональной линии: все фреймы повышают СУТ.

### Реактивные фреймы

Основной индекс — проблемная ситуация / триггер. Дополнительно фиксируется линия источника проблемы, если она определима. Подгруппы реактивных фреймов по типам проблемных ситуаций будут вводиться после инвентаризации.

### Утилизация времени

Функциональная группа, определяемая контекстом свободного или вынужденно незанятого времени; не отдельная линия.

### Ритуалы / фрейм-сеты

Композиционная группа. Ритуал может включать один или несколько фреймов и не отменяет их собственной классификации.

## Связь с линиями и метанавыками

- Для проактивных фреймов связь с линиями определяется видом интеллекта, способность которого требуется для выполнения фрейма.
- Для реактивных фреймов линия относится к источнику проблемной ситуации.
- Связь с метанавыками хранится отдельно и является many-to-many.

## Принцип ведения каталога

Не создавать отдельную F-карточку для каждого примера реализации. Новая F-карточка появляется, если есть самостоятельный механизм или существенная процедура.

Одно и то же внешнее действие может относиться к разным фреймам в зависимости от функции, а также быть фреймом или перманентной практикой в зависимости от временного горизонта и цели применения.
