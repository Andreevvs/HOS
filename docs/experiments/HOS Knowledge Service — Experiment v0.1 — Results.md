# HOS Knowledge Service — Experiment v0.1 — результаты

**Дата запуска:** 2026-09-07  
**Команда:** `python -m unittest discover -v`

## Итог

Автоматизированный набор содержит 5 evals и 6 негативных тестов. Последний локальный
запуск: **11 tests passed**. Canonical KB во время тестов не изменяется: E2 работает с
копией документа во временном каталоге.

## E1–E5

| Eval | Результат | Проверка |
|---|---|---|
| E1 Exact retrieval | PASS | Текст результата побайтно декодируется в тот же полный документ, что и канонический источник; режим registry — `whole_document`. |
| E2 Version propagation | PASS | После временного изменения и rebuild меняются `text` и `source_sha`; временная копия удаляется. |
| E3 Semantic retrieval | PASS (демонстрация на одном контрольном запросе) | В top-8 фиксированного запроса присутствуют канонические источники `Метанавыки`, `Архитектура уровней развития`, `Голографичность` и фрагменты по линиям развития; provenance проверен. |
| E4 Missing canonical object | PASS | `Экспресс-тест уровня развития v9.7` возвращает явный `not_found`, без fallback. |
| E5 Provenance | PASS | Для exact и каждого результата search проверяются существующий `source_path` и SHA-256 конкретной редакции. |

E3 демонстрирует работоспособность semantic retrieval на одном заранее заданном контрольном запросе, но не подтверждает его общее качество или пригодность для всего множества запросов HOS. Для такого вывода нужен отдельный экспертно размеченный benchmark и серия проверок на фиксированном наборе запросов.

## Негативные тесты

Все проверки прошли: неизвестный id; пустой semantic query; отсутствующий либо
переименованный `source_path`; duplicate id; изменение источника после build;
provenance conflict/stale index при search. В последних двух случаях выдаётся явный
`StaleIndexError`, устаревший текст не возвращается.

## Вывод по гипотезе

**Детерминированная часть гипотезы Knowledge Service v0.1 предварительно подтверждена:** E1, E2, E4 и E5 показывают воспроизводимое точное получение канонического объекта, распространение новой редакции, явный отказ для отсутствующего объекта и проверяемый provenance без использования монолитного Runtime.

**Semantic retrieval пока только продемонстрирован:** E3 показал получение практически связанных канонических источников на одном контрольном запросе. Этого недостаточно для подтверждения общего качества semantic retrieval.

Таким образом, эксперимент поддерживает архитектурное решение разделять детерминированный exact retrieval и поисковый retrieval, но не фиксирует конкретную технологию semantic search и не подтверждает её качество за пределами текущего контрольного случая.

Ограничения и нерешённые архитектурные вопросы перечислены в техническом README.
