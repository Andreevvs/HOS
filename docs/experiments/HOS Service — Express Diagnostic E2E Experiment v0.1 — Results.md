# HOS Service — Express Diagnostic E2E Experiment v0.1 — результаты

**Исходный прогон:** 2026-09-08  
**Текущая редакция:** после утверждения предварительной гипотезы L/ИУТ и UI-замены вопроса.

## Статус

Исходная версия прототипа прошла локальный набор E1–E15, но после изменения канонической
методики критерии итоговой интерпретации изменились. Поэтому старый PASS нельзя считать
достаточным подтверждением текущей редакции.

В текущую ветку добавлены проверки утверждённых контрпримеров и ограничений:

| Профиль / инвариант | Ожидаемое поведение |
|---|---|
| успешный L3 с хорошим текущим качеством жизни | остаётся гипотезой L3; контекст не повышает уровень |
| яркий, но хаотичный L4 | не демотируется в L3 только из-за средних Q6/Q9 |
| возможный L5 в тяжёлом периоде | L4 с признаками возможного L5; L5 не подтверждается |
| все 12 ответов = 10 | не выдаётся L6 и не подтверждается L5 |
| высокие Q5/Q9 при низких Q6/Q7 | последовательность блокирует гипотезу L4 |
| любой результат | нет арифметического ИУТ; выдаётся диапазон уровня и ограничение |

Дополнительно сохраняются проверки exact retrieval, Q1→Q12, диапазона ответов 0–10,
запрета skip/scale change/intermediate interpretation, session pinning, fail-closed при
недоступном canonical object, отсутствия hardcoded копии вопросов и HTTP round trip.

## Изменение архитектуры результата

Старая версия выдавала только контекстный профиль и явно не присваивала L. После
утверждённого изменения канона результат строится по цепочке:

`12 ответов → профиль текущей жизни → предварительная гипотеза L → диапазон ИУТ → уверенность + комментарий`.

Это не превращает экспресс-тест в полную диагностику: прохождение кризисов по 12
самооценкам не подтверждается, L5 остаётся только возможностью, L6 находится вне
разрешающей способности теста.

## Технические ограничения

Степень уверенности пока не имеет отдельной канонической вычислительной шкалы; executor
использует явную техническую эвристику. Выбор трёх высоких и трёх низких показателей —
также техническое правило presentation-слоя внутри разрешённых каноном 2–4.

Knowledge Service по-прежнему использует exact whole-document retrieval и сохраняет
snapshot/source_sha в session. Старые редакции не являются отдельным историческим
хранилищем. Web-сессии in-memory; production TLS, privacy controls, distributed storage
и observability вне этого эксперимента.

## Что ещё требуется для PASS текущей редакции

1. Запустить `python -m unittest discover -v` на актуальной ветке и получить полный PASS.
2. Выполнить ручное прохождение в браузере и проверить, что каждый новый вопрос заменяет предыдущий.
3. Проверить итог минимум на пяти контрольных профилях выше.
4. Только после этого считать локальный E2E текущей редакции подтверждённым.
5. Публичный внешний URL остаётся отдельным deployment-критерием и не должен считаться проверенным локальным тестом.
